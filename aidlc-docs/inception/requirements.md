# Requirements Analysis

## Intent

JAWS FESTA 2026 前日イベント（酒蔵見学）から着想を得て、**杜氏（とうじ）の役割を体験的に理解できる**
Web アプリを AWS 上に構築する。

## 背景：杜氏とは

杜氏は酒蔵の製造責任者であり、蔵人（くらびと）を率いて酒造りの全工程を指揮する。
蔵元（経営者）の注文した酒質を、その年の米や気候の状態を読みながら実現するのが仕事である。
本アプリでは「判断の連続」としての杜氏の仕事を、シミュレーションで体験させる。

## 機能要件

| ID | 要件 |
| --- | --- |
| FR-1 | 蔵元からの「注文」（目指す酒質）と、その年の条件（米の硬さ・冬の寒さ）が提示される |
| FR-2 | 利用者は杜氏として次の判断を順に行う：蔵人の配置／原料米／精米歩合／浸漬時間／製麹／酒母／醪の温度管理（3回）／上槽時期・アル添・搾り方／火入れ |
| FR-3 | 各判断に「杜氏の判断ポイント」の解説と、蔵人からの報告（ヒント）を表示する |
| FR-4 | 醪の工程では、品温とボーメの推移をグラフで確認しながら温度操作を行える |
| FR-5 | 結果として、特定名称（純米大吟醸など）、日本酒度・酸度・アルコール度、香り・旨味・キレ・綺麗さ、注文への適合度、総合評価、改善コメントを表示する |
| FR-6 | 結果を「蔵の記録帳」として DynamoDB に保存できる（杜氏名・酒銘を付ける） |
| FR-7 | 最近の記録一覧、記録の詳細表示、番付（スコア上位）を閲覧できる |
| FR-8 | 杜氏・蔵人の役割と酒造り工程を解説するページを持つ |
| FR-9 | サーバー側で結果を再計算し、改ざんされたスコアを保存させない |

## 非機能要件

| ID | 要件 |
| --- | --- |
| NFR-1 コスト | 完全サーバーレス。常時起動のリソース（NAT Gateway、EC2、RDS、ALB 等）を使わない。低トラフィック時は無料利用枠内でほぼ 0 円 |
| NFR-2 デプロイ | AWS CDK で定義し、**cdkd**（CDK Direct）で高速デプロイ／削除できる |
| NFR-3 配信 | フロントエンドは CloudFront から配信し、S3 は非公開（OAC） |
| NFR-4 記録 | DynamoDB（オンデマンド課金）を利用。古い記録は TTL で自動削除 |
| NFR-5 セキュリティ | Lambda Function URL は IAM 認証とし、CloudFront（OAC）経由でのみ呼び出せる。入力値はサーバーで検証する |
| NFR-6 利用環境 | スマートフォンでも操作できるレスポンシブ UI。ログイン不要 |

## 対象外

- ユーザー認証（Cognito）：コスト・手間に見合わないため対象外。記録は匿名で共有される
- WAF：月額固定費（約 5 USD〜）がかかるため既定では対象外
